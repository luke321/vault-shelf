# 0009 — The docs site is a live demo, built from the fixture

`docs/` is a GitHub Pages site — `_config.yml`, `index.md`, `features.md` — and
`docs/demo/index.html` is a **real export of the standalone page**, committed. Ported from
Vault Graph's issue #90, which did the same thing first (`a0667df`).

## Why a page and not more clips

The gallery this repository shipped with was a table with one row in it saying *(none recorded
yet)*, and the plan behind it was one clip per feature. A clip is the right thing for a
feature you cannot try — a folder hidden by default, a camera reset — but this product's whole
pitch is that **one note has six addresses**, and a person believes that in about four seconds
of clicking and never from watching somebody else click.

The exporter already produces exactly the artifact a demo page needs: one self-contained HTML
file, no build step, no server, nothing fetched. Publishing one costs a copy and gains the
only demonstration that answers the question people actually have.

Clips are not cancelled; they are demoted. The hero still opens the site, and
`docs/features/` still holds the per-feature recipe scaffold.

## The fixture, not the mirror, and not a real vault

`design/0013` says films are shot in a **mirror** because a fixture is even where a real vault
is lopsided. That argument is about the camera, and it does not carry to a page somebody
drives themselves:

| | |
|---|---|
| a **film** shows you one path through a vault | so the vault's real lopsidedness is the whole content of the shot |
| a **live page** is driven by the visitor | so what it needs is a vault that is legible, honest about its own shape, and provably nobody's |

And the fixture turns out not to be flat where it matters. Measured on the committed export:
394 notes over fifteen years, **419 books across six shelves**, of which the five visible ones
draw 187 spines and 20 plaques;
the Encyclopedia's `0-9` volume holds 184 notes against single-note volumes either side of it,
which is `design/0011`'s log scale doing visible work. The People shelf reports **394 unique
notes over books holding 500 places**, which is the unique-membership law legible on the page
without a word of explanation.

The deciding argument is the other one. A mirror is derived from somebody's real vault, and
`.gitignore` keeps `mirror-vault/` and `.mirror-source` out of the repository for that reason.
Committing a page built from one puts a real vault's *shape* — its folder counts, its dates,
how many notes each person is in — into a public repository permanently and by a route nobody
would think to check. The generated fixture is a **declaration** (`decisions/0004`): its
generator is in the repo, its seed is in the repo, and anyone can rebuild it byte for byte.

The vault is exported under the name **`Everything`**, the same rename `design/0007` gives the
recorder, because `demo-vault` in the corner of a demo says nothing to anybody.

## The one rule this bends

`CLAUDE.md` says *never a built `vault-shelf.html` in anything that reaches the repo*, and
`.gitignore` enforces it with `vault-shelf*.html`. `docs/demo/index.html` is that file under
another name, committed on purpose.

The rule exists because an export **contains every note title, path, tag, person and body in
plain text** — which is a statement about the *vault*, not about the file format. An export of
a declared fixture carries nothing that was not already generated by a script in this
repository. So the rule stands as written for every vault that is not a fixture, and the
exception is one path, reviewed, regenerated by one command:

```bash
node scripts/make-vault.mjs --notes 1200 --out <scratch>/Everything   # the name in the corner
node src/build-shelf.mjs --vault <scratch>/Everything --out docs/demo/index.html
```

**`--notes 1200`, not the whole vault, and that is a size decision rather than a shape one**
(`decisions/0014`). An export carries every note's body, so the declared 5,000-note vault
exports to 5.3 MB — eight seconds of blank page on a phone, and a megabyte of churn in the
repository every time it is regenerated. 1,200 notes is ~1.4 MB and is the same declaration
with a smaller `--notes`: the generator's own guard still has to pass on it, so the cut is
still a vault with a dense recent year, an empty year, undated notes and a people tail rather
than a truncation. Below about a thousand the guard refuses, which is the size floor stated
out loud rather than discovered.

`scripts/check-pii.mjs` reads every tracked file, so the committed export goes through the
same deny list as everything else — a demo built from the wrong vault fails a gate rather than
going unnoticed.

## Why the clips are linked absolutely

Pages publishes only what is inside the configured source directory (`/docs`), so a relative
path from `docs/index.md` to the repo-root `assets/` folder 404s on the built site even though
it renders correctly in GitHub's own markdown view. Both pages point at
`raw.githubusercontent.com/luke321/vault-shelf/main/assets/...`, which works in both places
without moving or duplicating the clips.

## What was rejected

**A workflow that builds the site.** `jekyll-theme-midnight` is one of the themes Pages builds
itself, and `assets/css/style.scss`, which repaints it in the product's own dark palette
(github#1), is compiled by that same build; a workflow would add a CI job, a Gemfile and a
lockfile to keep current, for a page with no build step in it. Vault Graph took the same view —
it added no workflow either.

**Regenerating the demo in CI.** The fixture's `--end` defaults to today, so a rebuild produces
a different file every day and the diff would be the whole 377 KB. The export is refreshed when
somebody decides the demo has gone stale, which is the same call the hero already asks for.

**Publishing from `develop`.** Pages reads `main`, which is where the README the site repeats
already points. The site therefore describes the released plugin rather than whatever is in
flight.

## Turning it on, and the thing that has to happen first

Pages is a repository setting, not a file, so it is one API call and it is recorded here
because nothing in the tree shows it happened:

```bash
gh api -X POST repos/luke321/vault-shelf/pages \
  -f 'source[branch]=main' -f 'source[path]=/docs'
```

**It is refused today**, with `422 Your current plan does not support GitHub Pages for this
repository`. The reason is not the plan and not the files: `vault-shelf` is **private** and
`vault-graph` is public, and Pages on a free account needs a public repository. Vault Graph's
call went through for that reason and no other.

So the site has one prerequisite, and it is a decision only the owner can take: **the
repository goes public.** Nothing else about the port changes — the same `docs/` builds the
moment the switch is thrown, and the call above is the whole of the rest.

The same prerequisite covers the clips independently. `raw.githubusercontent.com` serves a
private repository's files only with a token, so the hero on `index.md` is a broken image until
the repository is public whatever Pages is doing. There is no arrangement of files that gets
around either one, which is why neither was worked around.

Until then, `README.md` names the site without linking to it — the way Vault Graph's `6801153`
did for its own window — and the links go in once Pages reports a build succeeded.
